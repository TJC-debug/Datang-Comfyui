# 大汤自制节点系统

`Datang-Comfyui` 是大汤自用 ComfyUI 节点的统一项目。当前源码版本为 `0.4.57`，以本机 ComfyUI `0.3.75`、前端 `1.30.6` 为兼容目标。

## 0.4.57：节点组必需资源恢复保护

节点组关闭时会保存成员原执行模式；历史状态可能把同组 `CLIPLoader`、`UNETLoader` 或 `VAELoader` 错记为继续 bypass，同时把依赖它们的编码、LoRA 或 VAE 节点记录为正常运行。`0.4.57` 在同步节点组时只检查明确的必需 `CLIP / MODEL / VAE` 输入：若下游恢复为运行、同组资源源节点却恢复为 bypass，就把该资源源节点修回正常模式。可选资源输入、关闭状态、其他节点模式、连线和用户参数不变。

本修复与 PS_AI `1.7.0-dev.137` 的发布期二次保护配套；现有受影响工作流在部署后重新打开并保存/发布一次，才能让纳贝取得修复后的发布包。本机与云端尚未部署，真实保存重载、PS_AI 发布、纳贝执行和 Photoshop 结果仍需分别验收。

## 0.4.56：大汤重新打光提示词

节点类型 `DatangRelightingPrompt`，分类“大汤自制节点/提示词”。它是专用的重新打光提示词节点，不再提供通用 JSON、动态槽位或作者管理窗口；原有“提示词开关板”和模型选择器不变。

画布只显示 10 个中文原生下拉：“主光方向、人像布光法、光线质感、明暗与光比、色温与色彩、阴影形态、补光与控光、高光与材质、场景光源与光效、风格预设”。“重打光程度”及其三条后台文本已完整移除；每类都默认“不指定”，不会被迫叠加效果。执行时，节点按固定大类顺序把所选名称映射为后台完整英文提示词并合并为一个标准 `STRING`；界面和 PS_AI/纳贝只看到中文名称，持有插件源码的人仍可读取映射，因此这是界面收口而不是加密。

相比最初六组设想，本版补齐了容易遗漏、但会直接影响重打光稳定性的内容：

- 旧 `0.4.55` 节点保存的 11 个顺序值会在重新加载时自动丢弃第一项，并把后十项按大类名称恢复，防止删除首项造成参数整体错位；新保存结果只包含 10 项。
- “人像布光法”覆盖单灯、双灯、三点、蝴蝶、环形、伦勃朗、环路、分割、宽光、窄光和蛤壳光。
- “阴影形态”独立控制软硬、长短、百叶窗、窗框、树影和近乎无影，避免只写光源却遗漏投影结果。
- “高光与材质”覆盖自然/柔和/镜面高光、压制反光、金属与皮肤高光，兼顾人物和产品。
- “场景光源与光效”覆盖窗光、黄金时刻、阴天、月光、室内实景灯、体积雾、丁达尔、光晕、耀斑、散景、焦散和舞台光束。

节点不加载模型、不修改图片、不读本地 JSON、不访问网络，也不增加 pip/npm 运行依赖。兼容脚本只负责旧 11 值工作流的一次性位置迁移，不增加可见按钮或管理界面。节点可连接任何接收 `STRING` 的提示词入口；具体模型是否完全遵循每一项仍属于模型和工作流的真实生成效果，必须用目标模型分别验收。

开源核查发现：`ComfyUI-IC-Light-Native` 与官方 `IC-Light` 提供重打光模型/工作流，`ComfyUI-Prompt-Preset-Selector` 提供文件预设选择，`comfyui-relight` 提供无需扩散模型的像素级灯光预设；没有一个现成实现同时满足本项目的固定中文多大类、隐藏完整提示词和 PS_AI/纳贝原生发布合同。本节点因此只沿用 ComfyUI 标准下拉与 STRING 合同，没有复制第三方运行代码，也不额外安装整套节点包。

本次自动测试、部署与真机结果见 `docs/重新打光提示词验收.md`。用户已确认移除“重打光程度”后的 10 项真实画布交互通过；该确认不能替代 PS_AI 人工发布、纳贝十类参数、目标模型生成、Photoshop 结果或云端端到端验收。下文旧版本记录均为历史证据。

## 当前节点

### 大汤懒执行条件分支

- `DatangBooleanConstant` 输出标准 BOOLEAN；`DatangLazyIfElse` 接收开关、开启值和关闭值，并把两个值输入声明为 ComfyUI 后端延迟输入。
- 后端只请求当前开关选中的缺失支路，未选中的采样器和处理链不会为了生成条件节点的输入而提前执行。
- 该节点用于 PS_AI `1.7.0-dev.132` 发布的普通运行时大汤组，不修改画布中的原工作流、保存节点和用户开关；PS_AI 与 Datang 必须成对同步。
- `0.4.42` 在开关组元数据中只追加历史成员显示顺序。原生组框移动或成员几何重算造成临时丢失、重入、换序时，已有成员仍按首次记录顺序显示在 PS_AI；新成员追加到末尾，节点执行模式与连线不变。
- `0.4.52` 为“大汤图像比例裁剪”增加可选输出尺寸：四种实际裁剪比例可保持裁剪尺寸，或按最长边、最短边、宽度、高度等比缩放到指定像素；默认仍不缩放，旧工作流无需迁移。“保持原图比例（不裁剪）”继续无条件原样旁路，不受输出尺寸设置影响。

### 大汤人物定比裁剪

- 接收单张人物照片，保留 `1:1`、`3:4`、`4:5`、`2:3` 四种画布比例，以及头像照、标准证件照、胸部证件照、半身证件照四档头部占比；还可微调头部大小和人物上下、左右位置。
- 节点根据主要人脸估算头部范围，再直接从原图取得目标比例的矩形像素；不再缩放或重采样整张人物图，因此不会拉宽、压扁或因缩放变糊。
- 当目标裁剪框超出原图时，保留目标头部比例和位置，以原图四周边缘像素的中位颜色填充缺失区域；“填充区域遮罩”中白色表示填充像素、黑色表示原图像素。
- 为避免极端紧脸原图按半身比例生成异常大画布，输出单边最多为对应原图的 2 倍，同时受 `8192px` 和约 2400 万像素上限保护；触发限制时仍不缩放人物，但状态会标记 `needs_review`。
- 输出包括裁剪结果、带头部框与目标线的裁剪预览、填充区域遮罩和 JSON 状态信息。状态包含原图坐标系裁剪框、边框填充色、填充像素数及 `resampled: false`。
- 未检测到人脸时不会伪装成功，而是在原图内按画布比例居中裁剪并标记 `needs_review`；检测到多张人脸时选择主要人脸并要求复核。
- 当前环境存在 `mtcnn-runtime` 时优先使用 MTCNN；未安装、初始化失败或单次检测异常时回退到现有 OpenCV Haar。Datang 不会自动联网下载模型，也不会为了这个节点同时安装 `opencv-python` 与项目既有的 `opencv-python-headless`。
- 为兼容原 `ComfyUI-NabeiPortraitComposition-V1` 示例和 `0.4.39` 工作流，内部节点类型继续使用 `NabeiPortraitComposition`；画布显示名改为“大汤人物定比裁剪”，现有节点无需重新连线。
- 本节点负责把一张人物照片裁成目标比例；“大汤证件照智能排版”负责把已经制作完成的证件照按冻结槽位排列到相纸。两者职责不同，不会自动替换现有排版节点。

### 大汤证件照快速裁剪

- 这是 Datang 自有的证件照规格裁剪节点，内部类型为 `DatangQuickIdPhotoCrop`；它与“大汤人物定比裁剪”并存，不替换旧节点或自动改写工作流。
- 参数和四个输出沿用现有证件照裁剪工作流的使用习惯：人脸矫正、19 个正式尺寸预设和自定义尺寸、厘米/像素、DPI、脸部大小、垂直偏移、检测尺寸限制、填充模式，以及“裁剪后图像 / 是否扩图 / 扩展遮罩 / DPI”。
- 预设厘米规格按当前 DPI 换算成精确像素；电子证件照预设使用各自固定 DPI。输出始终缩放到目标像素尺寸，适合继续连接“大汤证件照 DPI 保存”或“大汤阶段结果保存”。
- 人脸定位复用 Datang 已有的 MTCNN/OpenCV 检测链，不导入 MediaPipe，不要求调整 protobuf，也不会自动下载模型。`尺寸限制`只约束检测预览，不先缩小正式原图，避免无必要地损失裁剪来源清晰度。
- 打开人脸矫正且检测器提供双眼关键点时，会先校正双眼水平；裁剪超出原图或旋转产生空区时，按边框中位色或用户填写的十六进制颜色补齐，并输出对应遮罩。
- 两套人脸检测均失败时会明确停止并提示换用正面清晰照片，不再把原图冒充为裁剪结果。单边和总像素仍受安全上限保护。
- `0.4.48` 不再把固定尺寸和比例选项放在同一个节点。`DatangQuickIdPhotoCrop` 已恢复为 `0.4.47` 的原界面和行为，旧工作流、控件顺序、固定尺寸计算及四输出完全不需要迁移。

### 大汤证件照比例裁剪

- 这是独立新节点，内部类型为 `DatangIdPhotoRatioCrop`；不是简化成只有比例下拉框，而是完整保留快速裁剪的人脸矫正、单位、DPI、脸部大小、垂直偏移、检测尺寸限制、填充模式、自定义填充色，以及“裁剪后图像 / 是否扩图 / 扩展遮罩 / DPI”四输出。
- 固定证件照尺寸选择改为唯一的“比例预设”，支持“保持原图比例（自动识别）”“保持原图尺寸（宽高不变）”、`1:1 / 3:4 / 4:5 / 2:3` 和自定义整数比例；节点始终按这里选择的一项执行，不存在开关、跟随或上下参数优先级。
- “保持原图比例”动态读取当前输入图宽高，只把人脸构图裁剪框调整为同一比例，不固定输出像素；常见可约分尺寸使用精确整数比，极端互质尺寸才退回一像素级近似。“保持原图尺寸”先按相同原始比例和人脸参数构图，再等比恢复为输入图精确宽高，因此脸部大小和垂直偏移仍然有效。
- 其他固定比例保留由人脸大小计算出的来源像素尺度，只把裁剪宽高修正为比例的整数倍；不强制重采样到证件照固定像素。`单位`保留完整参数合同，但比例本身没有物理单位；`DPI`继续作为第 4 输出传递，不参与强制缩放。
- 需要传统一寸、二寸或考试报名照精确像素时使用旧“证件照快速裁剪”；只需要构图比例且后续仍会经过模型时使用本节点。

### 大汤图像尺寸回正

- 接收“处理后图像”和“尺寸参考图像”，只读取参考图的宽高，把最终输出严格恢复到同样的像素尺寸；不写死证件照规格，也不依赖第三方尺寸节点。
- 默认“仅补齐或裁掉边缘（不缩放）”适合模型只少出或多出几个像素的情况：居中裁掉多余边缘，缺少区域用处理后图像边缘中位色补齐，已复制进结果的像素不重采样。
- 另提供“等比缩放后居中裁剪”和“直接缩放到参考尺寸”。前者不拉伸但会裁边，后者保证直接匹配但在比例不同时可能产生轻微形变，必须由工作流作者明确选择。
- 典型接法是把“大汤证件照快速裁剪”或“大汤证件照比例裁剪”的同一输出分成两路：一路进入模型，另一路接本节点的“尺寸参考图像”；模型结果接“处理后图像”。ComfyUI 会复用上游结果，不需要重复执行裁剪。
- 工作流有多个最终处理分支时，必须先完成分支选择，再把唯一结果接入本节点，最后连接保存节点；如果尺寸回正只放在某一个候选分支中，其他分支仍可能保留 VAE 的 8 像素对齐差值。

### 大汤图像比例裁剪

- 这是轻量通用比例节点，内部类型为 `DatangAspectCrop`。整图中心与人脸构图共用“保持原图比例（不裁剪）、1:1 正方形、3:4 常用证件照、4:5 竖版证件照、2:3 标准竖版”；不再提供自定义比例和自定义宽高。
- 开关在界面显示为“按人脸构图”，后端字段仍保留 `启用人脸识别`，因此旧工作流与 PS_AI 参数合同不需要迁移。关闭时完全不调用检测器：“保持原图比例”原样旁路，其他比例从整张画面中心取得最大矩形。
- “保持原图比例（不裁剪）”无论人脸构图是否开启都直接保留整张输入图，不运行检测器。选择其他四个比例并打开“按人脸构图”后，才复用现有 MTCNN/OpenCV 链逐张识别主要人脸，以人脸框宽度和“脸部大小”决定取景远近，以双眼中心和“垂直偏移”决定上下位置。
- 默认输出尺寸方式为“保持裁剪后尺寸（不缩放）”，因此原有两种构图模式仍只切取原图像素，不旋转、不缩放、不补边。选择四种实际比例时，还可明确改为按最长边、最短边、宽度或高度等比缩放到“目标像素”；另一边按裁剪比例计算并取最接近的整数像素。
- “保持原图比例（不裁剪）”会忽略输出尺寸方式和目标像素，继续返回输入图像本身。人脸未识别会明确提示关闭“按人脸构图”；同一 IMAGE 批次若各张人脸需要不同输出尺寸，保持不缩放时仍提示逐张处理，启用统一目标像素后可形成相同尺寸批次。
- 为兼容旧工作流，历史自定义宽高仍作为隐藏值保留，不在节点界面显示，也不会被 PS_AI 当作可发布参数。旧简写“保持原图比例”和“1:1”会自动迁移为完整文案；旧自定义宽高若正好对应现有预设会迁移到该预设，否则回到“保持原图比例（不裁剪）”，避免删控件造成脸部大小和垂直偏移错位。
- 本节点的“脸部大小”和“垂直偏移”只用于裁剪构图。需要双眼水平矫正、DPI、填充和扩展遮罩时仍使用“大汤证件照比例裁剪”；模型处理后还要恢复处理前精确宽高时，再接“大汤图像尺寸回正”。

### 大汤生活照打印裁剪

- 这是面向 Photoshop 普通用户的独立生活照裁剪节点，内部类型为 `DatangPhotoPrintCrop`；不修改或替换已经验收的证件照裁剪节点。
- 新界面只保留两种处理方式：“居中裁剪”和“保留全图并补边”，不做人物、动物或场景识别。为防止旧工作流的参数数组错位，历史“指定焦点裁剪”和“焦点位置”仍保留为后端兼容合同，但新画布会把旧节点迁移为居中并隐藏焦点控件，PS_AI 也不会把它作为普通可见参数扫描。
- 成品尺寸提供 5、6、7、8、10、12 寸及自定义尺寸；可选择跟随原图、横版或竖版，默认 300 DPI，并输出可连接的 DPI。
- 居中模式先在原图中取得与成品比例一致的最大区域，再统一重采样到精确输出像素，不做横纵拉伸。保留全图模式按比例完整装入，空白区域自动使用原图四周边缘像素的中位颜色补齐。
- `0.4.47` 根据本机查看反馈移除节点底部“构图预览”及后端临时预览保存，不再为了界面显示生成 ComfyUI 临时图片。旧预览版本留下的高节点会在加载时恢复为原生控件高度；两种可见方式和隐藏旧焦点参数的兼容逻辑继续保留。
- 输出依次为“处理后图像 / DPI / 补边遮罩”。前两个旧输出槽位保持原顺序，第三个标准 `MASK` 中白色表示“保留全图并补边”新增的边框区域，黑色表示装入的原图区域；居中裁剪或实际没有补边时返回全黑遮罩，可直接交给后续填充扩图流程。
- 节点一次只处理一张图片，文件夹和逐张批量继续由纳贝队列负责；不增加 OpenCV、人脸检测、智能构图、额外模型或联网依赖。

### 大汤证件照智能排版

- 接收一张已经制作完成的证件照和纳贝AI冻结的 `nabei.id_photo_layout/v1` 像素排版数据。
- 连接“裁剪预设尺寸”的宽、高和 DPI 后，节点面板会实时显示上游精确像素，锁定证件照尺寸和 DPI 控件，并隐藏会覆盖外部尺寸的快捷预设；断开连接后恢复手动规格。上游规格变化导致旧固定网格放不下时，仅在该次变化时回到自动铺满，避免带着无效网格执行。
- ComfyUI 节点内同时提供可视化手动排版界面：普通证件照与画布预设只显示名称，只有选择自定义尺寸或自定义画布时才展开单位、宽和高；保留厘米或像素自定义能力。
- 顶部“快捷排版”按5寸、6寸、7寸从上到下排列，提供5寸9张1寸、5寸4张2寸、6寸12张1寸、6寸6张2寸，以及7寸单人混排8张1寸竖版+4张2寸横放；其中5寸4张2寸固定为2列×2行并保留裁剪留缝。A4 50张不再占用快捷入口，但A4仍保留在输出画布枚举中。用户也可以把当前整套参数保存为个人预设，个人预设保存在当前浏览器本机，支持同名更新和删除。
- 快捷预设作为一次性参数指令，点击后立即套用但不保持高亮；“恢复默认”会回到节点初始参数，而不是把各项数值归零。预览中的中性人物轮廓跟随照片槽位横竖方向整体旋转，不再把竖向人物拉伸成横版。
- 排版方式默认“自动铺满”，系统按当前相纸、尺寸、方向、边距和间距计算可用网格；指定张数和固定行列进入高级排版设置，只有选择对应模式才显示相关控件。固定方向时不重复显示候选方案，有效布局不重复显示状态说明。
- 7寸单人混排模板在上方排列8张一寸竖版、下方排列4张二寸横放；排版合同支持每个照片槽位独立旋转，同一人物无需预先制作第二张横向输入图。
- 照片方向与画布方向分开控制：可保持输入图方向，或明确选择竖版/横版；最终合成会在输入图方向与目标方向不一致时整体旋转 90°，预览与真实输出采用同一规则。
- 已移除含义重叠且在固定网格下不明显的“易裁切/紧凑排版”按钮；照片间距直接控制疏密，裁切线用独立枚举开关控制，并在占位预览与最终合成中保持一致。
- 裁剪线只允许落在照片槽位以外的纸张空白区域；线段与任意照片相交时会自动裁短或隐藏，密排无空白时宁可减少内部裁剪线，也不覆盖照片像素。前端生成和后端执行均执行同一安全保护。
- 间距方案提供“影楼紧密、留缝裁切、自定义”：影楼紧密使用零外边距和零照片间距，使六寸横版可形成十二张一寸照的 6×2，以及六张二寸照的 3×2 常用模板；自动布局优先完整矩形网格。
- 参数无法完整排下时不再显示空纸：预览会绘制当前纸张内可合法放入的最大数量，并明确显示未排入张数；无效布局仍禁止提交执行。
- 节点面板内的滚轮会继续传递给 ComfyUI 画布缩放；只有高级 JSON 文本区本身仍可继续滚动时才由文本区消费滚轮。
- 鼠标位于节点自定义面板上时，按住中键拖动会继续平移 ComfyUI 画布，不被 DOM 面板拦截。
- 占位预览严格按最终画布像素、照片槽位坐标和宽高等比例绘制，并增加画布物理宽高标尺、照片尺寸说明和中性人像轮廓；它表达真实几何比例，但不冒充最终真人照片像素效果。
- 预览区域提高相纸显示上限、压缩容器固定留白，并让右侧尺寸说明与相纸顶部对齐；只改变界面空间利用率，不改变排版合同或最终输出坐标。
- 预览右侧摘要将画布尺寸、照片尺寸、行列与总张数固定为独立信息行；混排、无法完整排下和外部冻结布局也使用稳定的分行结构，不再依赖段落自动换行。
- 画布枚举覆盖钱包照、3R/5寸、4R/6寸、5R/7寸、6R/8寸、8R/10寸、8×12、10×12、12×18、5×5 方形相纸以及 A5/A4/A3；仍保留自定义画布，避免把设备专用长卷规格写死。
- 参数变化后在节点内即时显示无真人图的占位预览并生成同一份排版 JSON；原始 JSON 默认隐藏，只在高级查看区只读展示。纳贝AI传入的冻结布局仍可直接执行，不会被前端二次重排。
- 严格使用纳贝AI给出的画布、照片槽位和裁切线；节点只等比缩放并居中放入槽位，不拉伸、不自行增删或重排。
- 最终合成的人像缩放改用 Pillow Lanczos 高质量重采样；不额外锐化，不改变已验收的完整装入、居中留白和排版坐标。
- 高级排版设置提供 `DPI`，默认 300、范围 72～1200；厘米规格按 DPI 换算实际像素，像素规格保持作者输入的像素值不变。
- 节点左侧提供可选的 `输入DPI` 连接口，可接收其他节点的 INT DPI 输出。连接后外部值优先，并等比例缩放整套冻结画布、槽位和裁切线，不重新计算行列；未连接时继续严格执行高级设置生成的冻结像素布局。
- `0.4.36` 修复证件照智能排版节点在创建或加载时界面完全空白的问题：旧连线迁移只在节点进入画布且确实存在连线后执行，隐藏参数继续保留 ComfyUI 原生控件类型；可视面板先挂载后渲染，初始化失败时也会明确显示原因，不再留下空壳节点。
- `0.4.35` 修复旧工作流在新增外部规格接口后可能把图片连线错挂到内部 DPI 控件的问题：内部 DPI 不再伪装成可连接控件，旧错位连线会迁回唯一的图片入口；外部 `输入DPI` 已连接时不会再提前校验被旧数据污染的内部 DPI。
- 节点左侧新增可选的 `输入照片宽度`、`输入照片高度` INT 接口，可直接连接“孤海预设尺寸”等裁剪尺寸节点的宽高输出；该节点的分辨率输出继续连接现有 `输入DPI`。
- 外部宽高必须同时连接。连接后保持当前输出相纸画布、张数、行列结构和间距，在画布内按外部证件照像素尺寸重新居中排布；尺寸放不下时明确报错，不会缩小照片或扩大相纸。
- 单人标准网格支持外部宽高；一寸与二寸混排包含两种照片尺寸，拒绝用一组外部宽高整体覆盖。未连接外部宽高时，纳贝冻结布局和原 ComfyUI 手动设置行为不变。
- 支持同一输入批次逐张排版；输出排版图、包含 `layoutId`、画布像素、槽位数量及 DPI 的回执，并提供可连接的 `DPI` 输出接口。
- 排版节点只决定像素布局，不直接写文件元数据；需要真实 DPI 文件时，将排版图和 DPI 接到“大汤证件照 DPI 保存”。ComfyUI 原生 `SaveImage` 行为保持不变。

### 大汤证件照 DPI 保存

- 这是明确的真实输出节点，接收图片、DPI 和文件名前缀，将 PNG 保存到 ComfyUI 正式输出目录并写入横纵一致的 DPI 元数据。
- DPI 默认 300、范围 72～1200；可直接连接“大汤证件照智能排版”的 DPI 输出，避免重复输入。
- 保留 ComfyUI 标准工作流元数据和结果图片回执，ComfyUI-PS-AI 与纳贝会把它识别为正式结果节点。
- 只影响明确使用此节点的工作流，不替换或修改普通 `SaveImage`、`PreviewImage` 和历史工作流。

### 大汤阶段结果保存

- 接收图片、阶段序号和阶段名称，作为真实输出节点把当前阶段写为 PNG，不是预览节点或假保存。
- `0.4.38` 增加可连接的 `是否保存` BOOLEAN 接口。未连接时默认保存，保持旧工作流兼容；连接阶段开关且为关闭时返回空结果，并通过 ComfyUI 延迟输入机制不读取图片、不触发仅由该保存节点依赖的上游处理支路。
- `0.4.37` 增加可连接的 `输入DPI` INT 接口。连接裁剪尺寸或排版节点的 DPI 输出后，阶段 PNG 写入真实分辨率元数据；未连接时保持旧工作流原行为，不擅自写入默认 DPI。
- ComfyUI 输出子目录固定使用 `datang-stage-result-v1/NN_阶段名`；非法文件名字符会被替换，阶段序号限制在 1～999。
- 配套 ComfyUI-PS-AI 会发布阶段顺序和名称；纳贝进行文件夹批量时，在该阶段目录下继续保留输入文件夹的相对结构和原文件名。
- 只影响明确放入该节点的特殊工作流。普通 `SaveImage`、单张处理、其他工作流、历史 JSON 和发布包均不迁移、不改写。

### 大汤人像快速美颜

- 输入为 `IMAGE + MASK`，输出为 `IMAGE`，保持原画布宽高与批次数量；裁切范围、皮肤识别、图层回传和批量来源由上游节点、纳贝与 Photoshop 负责。
- 节点不做人脸检测、不推算脸部区域。严格按外部皮肤遮罩处理：白色区域完整处理，黑色区域逐像素保持原样，灰色区域按遮罩权重处理。
- 提供美颜强度、磨皮、美白提亮、纹理保留、黑眼圈淡化、瑕疵皱纹淡化六个 0～100 滑杆。美颜强度为 0 时严格返回原输入。
- 磨皮、美白提亮、纹理保留和瑕疵皱纹淡化只决定处理方式；黑眼圈淡化改为对遮罩内局部暗沉进行保守提亮，不依赖眼睛坐标。
- 不使用扩散模型、VAE、采样器，不重绘五官，不改变脸型或画布结构；0.4.25 的 YuNet 人脸检测代码和模型已移除。
- 单张遮罩可以广播到同批多张图片；遮罩尺寸不一致时按图像尺寸平滑缩放，遮罩批次既不是 1 也不等于图片批次时明确报错。
- 自动测试验证遮罩合同、黑区严格旁路、灰度权重、尺寸缩放、批量广播、透明通道和算法实际生效；真实皮肤遮罩与最终观感仍需 ComfyUI 实机验收。
- 节点底部提供“恢复默认”，一次恢复美颜强度 60、磨皮 45、美白提亮 18、纹理保留 70、黑眼圈淡化 30、瑕疵皱纹淡化 25；图像和遮罩连接不受影响。

### 大汤人像痘印精修

- 这是独立的可选精修节点，不替换“大汤人像快速美颜”，也不改变现有工作流；输入为 `IMAGE + MASK`，输出精修图像和实际痘印遮罩预览。
- 节点不识别人脸、不生成皮肤遮罩，只在上游提供的皮肤遮罩内检测局部深色斑点和红印，并按最大瑕疵尺寸过滤大块阴影、头发和结构区域。
- 使用本机已有的 Big LaMa 模型只重建检测到的小块瑕疵，再按修复强度与边缘羽化局部融合；外部皮肤遮罩之外保持原像素，透明通道和画布尺寸不变。
- 模型优先读取 `ComfyUI/models/inpaint/big-lama.pt`，也可直接复用 `custom_nodes/comfyui-lama-remover/ckpts/big-lama.pt`；节点不会联网下载模型，缺失时会明确报错。
- 自动检测无法从语义上保证区分痘印、雀斑和需要保留的痣。正式批量使用前应先查看“痘印遮罩”输出，并通过检测灵敏度、最大瑕疵尺寸、深色斑点修复和红印修复控制范围。
- “五官边缘保护”默认 78：根据上游皮肤遮罩中的眼睛、嘴巴等黑色孔洞边缘，以及连续强边缘结构，排除邻近区域；它不做人脸识别或五官坐标推算。眼周仍被选中时可继续提高，痘印靠近遮罩边缘而被漏掉时可降低。
- 节点底部提供“恢复默认”，只恢复精修参数，不修改图像、皮肤遮罩连接和工作流连线。

### 提示词开关板（无限槽位）

- 无限增加提示词槽位，支持单选和多选。
- 每个槽位有独立名称、文本、开关、删除与拖动排序。
- 只合并已启用且非空的提示词，保留自定义分隔符。
- 继续使用原节点类型 `PromptSwitchboard`，旧工作流可直接加载。

### 大汤节点组开关

- 先在画布选择一个或多个节点，再在画布空白处右键选择“`大汤：将选中的 N 个节点设为可开关组`”。
- 自动创建 ComfyUI 原生黄色组框，开关直接显示在组标题栏，不再显示独立控制节点。
- 拖动组框会带着内部节点一起移动，拖动右下角可缩放组框。
- 关闭开关会把当前组成员切换为 Bypass，并记录它们原来的模式。
- 重新开启，或在关闭状态下把节点移出组框时，会恢复对应节点原模式。
- 节点进入或移出关闭状态的组时，会自动旁路或恢复。
- 组名、内部控制器标题和 `Enable <组名>` 标签自动同步，供 ComfyUI-PS-AI 识别和发布。
- 内部控制器仍随工作流保存，但不再占用画布空间；旧工作流中的未连接控制节点会自动收进对应组标题栏。
- 建组时保留其他模块相对顺序，并把内部控制器插到成员之前，避免 PS_AI 分组开关顺序冲突。
- 新建组会为标题和开关保留安全高度，成员节点不会遮挡标题栏。
- 删除大汤黄色组时会一并删除它专属的隐藏控制节点，并清理 PS_AI 排序记录。
- `0.4.1` 将组与正式控制器建立为单次索引，画布绘制不再逐帧嵌套扫描全部节点；无变化状态不再重复写入，低频安全同步也不会自动删除旧工作流中的重复隐藏控制器。
- `0.4.2` 以保存的控制器 ID 作为组绑定主键；修改组名后，画布标题栏开关、PS_AI 预览开关和发布分组继续指向同一个真实组，不再因旧名称失配而消失或失效。

### 大汤节点组状态标记

- 把节点放进一个“大汤节点组开关”组框后，它会自动绑定最内层的大汤可开关组；未绑定时按空值处理。
- 该标记节点是组内唯一不会随普通成员一起 Bypass 的状态节点：组开启时输出非空 `状态标记`，组忽略时输出 `None`。
- `状态标记` 可直接连接 EasyUse“是否为None”；同时提供 `是否为空` 与 `组已启用` 两个 BOOLEAN 输出，可省略额外判断节点。
- 内部同步参数不提供手动编辑，也不作为 PS_AI 普通参数发布；ComfyUI 标题栏或纳贝触发的真实节点组状态变化都会同步到标记节点。

### 大汤布尔与非

- 接收两个标准 BOOLEAN“是否为空”结果；两个输入默认均为 `true`，未连接时最终输出保持关闭。
- 只有两个输入都为 `true` 时输出 `false`；任意一个输入为 `false` 时输出 `true`，用于组合“提示词开关板为空”和“大汤开关组为空”的状态。
- 节点输出本身就是可连接的 BOOLEAN，不需要再串联一个布尔常量节点；不读取提示词、不控制组状态，也不依赖其他第三方节点包。

### 大汤无开关参数组

- 先在画布选择至少两个节点，再在画布空白处右键选择“`大汤：将选中的 N 个节点设为无开关参数组`”。
- 自动创建与可开关组一致的 ComfyUI 原生黄色组框，但不创建控制节点、不显示开关，也不改变任何成员节点的运行模式。
- 默认组名为“`大汤参数组`”，重名时自动追加序号；修改画布组名后，ComfyUI-PS-AI 会把该名称作为发布到 Photoshop 的组合模块名称。
- 组内至少有两个设置为“显示给 PS”的模块时，现有 ComfyUI-PS-AI 发布合同会把它们写入同一个 `display_package`，参数值和 ComfyUI 执行逻辑保持不变。

### 模型选择器（单选多槽位）

- 一个选择器连接一个已经“转换为输入”的模型下拉参数；它读取目标参数的真实选项，因此可用于 checkpoints、ReActor、放大模型及其他字符串模型列表，不写死模型目录。
- 默认保留两个槽位，可继续添加、删除和修改槽位名称；每个槽位保存一个真实模型值，节点高度随槽位数量自动调整。
- 槽位开关始终互斥且至少启用一个；节点只输出当前启用槽位的真实值，不自行加载模型，也不额外占用显存。
- ComfyUI-PS-AI 会把槽位发布为单选开关，并允许作者为每个槽位单独设置 Photoshop 显示名称；真实模型值仍保存在工作流和 API Prompt 中。

### 0.4.3 保险箱移除说明

- 已移除工作流保险箱的前端加载脚本、遮罩、管理员菜单和键盘/鼠标拦截，恢复 ComfyUI 原生节点选择、移动及跨工作流复制粘贴。
- 不修改现有工作流 JSON；历史 `datang_workflow_vault` 元数据保留但不再被读取或执行，便于需要时通过 Git 或仓库外备份恢复旧版本。
- 不修改提示词开关板、节点组开关、无开关参数组、模型选择器、PS_AI 参数发布及 ComfyUI 执行逻辑。
- 旧保险箱源码、测试和使用说明已从当前工作树移除；如需历史追溯只能查看 Git 历史或仓库外备份，禁止在后续优化中顺带恢复。
