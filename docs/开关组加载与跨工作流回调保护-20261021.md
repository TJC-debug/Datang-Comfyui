# 开关组加载与跨工作流回调保护

日期：2026-10-21，Datang-Comfyui 0.4.62，配套 PS_AI 仍为 dev.141，纳贝仍为 0.4.11。

用户反馈 dev.141 页面中，组头按钮仍显示“开启”，但点击不切换，PS_AI 左侧加载服装图也不再包在组开关内。用户随后返回直接打印的只读检测结果：loading=false；#加载服装参考图绑定controller_id=216、enabled=true，boundType=不存在；controllers=[]。已确认当前开关失效的直接原因是控制节点216缺失。现有结果不能确定历史删除动作恰好发生在何时，也不能认定是PS_AI141新改动直接删除。

## 独立复现

旧版绑定控制节点会排队 0/120/600ms 回调。节点脱离旧工作流后，回调通过 node.graph || app.graph 取得新工作流，按旧节点查组失败后删除控制节点。若新图复用同一编号，底层按编号删除会影响新节点。另一场景是当前图仍处于 configuringGraph、节点已恢复但组尚未恢复时，同步会把组当成已删除。

组头绘制在控制节点缺失时仍会读取组 flags 画出按钮；点击需要真实控制节点。PS_AI 左侧同样依赖真实控制节点，因此缺失会同时影响两处。当前用户检测已确认该组符合此情况。

## 修复

仅修改 web/datang_group_switch.js：统一检查 node.graph 必须是 app.graph、节点对象仍在当前图中、当前不在 configuringGraph；不再将 detached 节点回退绑定到 app.graph。延迟回调先校验归属再建立索引。加载期间不执行组同步、画布切换或 PS_AI 请求；afterConfigureGraph 后安排一次重新同步。标记节点的延迟回调也检查归属。用户真正删除当前组时，仍按原流程恢复成员模式并删除对应内置控制节点。

不在加载/轮询时自动创建节点、不改组框/连线/图片/提示词、不读取或清理浏览器缓存。新增用户主动操作的画布空白右键菜单“大汤：修复缺失的组开关”，可选择原组，只补回缺失控制节点。原编号空闲时复用216，被其他节点占用时让画布分配新编号，绝不覆盖原节点。原组对象、位置尺寸、连线、图片、提示词和历史成员记录保留；开关排到相关模块之前供PS_AI重新识别。已有正常控制节点时不重复创建。对于关闭状态或含单独忽略/停用成员的孤立组，因原状态缺失而拒绝猜测恢复，并说明原因。不恢复已移除的保险箱模块。缺失控制节点的历史工作流需先核对绑定和备份，只修复相关开关，不能通过整图覆盖恢复。
