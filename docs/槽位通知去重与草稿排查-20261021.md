# 保存发布兼容与草稿失败排查

日期2026-10-21。PS_AI dev.141、Datang0.4.61、纳贝RunningHub0.4.11；桌面1.0.91保持。

## 用户反馈与证据边界

用户确认Datang0.4.60槽位能修改、保存和切回，但PS_AI dev.140配纳贝0.4.10时，Ctrl+S及刷新重连后仍显示旧名称；同时停止操作后仍持续新增“保存工作流草稿失败”。截图中可辨识的404主要为/manager/badge_mode、view、favicon、user.css及workflows/.index.json，不能把它们直接等同于草稿写入错误。浏览器只读连接未接通；没有刷新页面、清存储或操作云端。尚缺首条draft/存储失败的底层错误，未判定为本轮通知引入、存储配额耗尽或平台后端故障。

核对官方ComfyUI新版workflowService/workflowStore的保存流程：原生保存可以直接走workflowStore.saveWorkflow/workflow.save，绕过旧extensionManager.workflow.saveWorkflow。旧PS_AI只包装后者，存在原文件保存成功但功能包未更新的兼容缺口。这是源码支持的跨版本缺陷，不是已读取当前云端安装源码的结论。官方草稿保存错误提示来自草稿持久化失败，和PS_AI功能发布是两条链路；不清草稿、不屏蔽错误、不开启/关闭持久化设置来制造通过。

## 本轮修复

PS_AI保留旧保存入口，同时观察api.storeUserData的成功源文件写入。仅workflows下的当前真实工作流JSON、响应ok且内容与当前画布一致时，排入一次发布；草稿、隐藏索引、设置、发布包、另一个文件、失败响应和加载期间不发布。调度只由实际保存触发，没有空闲轮询保存或失败重试。内部元数据保存受管理状态保护，不触发二次递归发布。保存后的新编辑未再次保存时不冒充已保存内容发布；切换工作流后不写新工作流的发布状态，错误归属原工作流。所有正常失败仍保留旧有效包和可见错误。

纳贝手动“刷新重连”对目录和正文加入新鲜查询，并绕过内存与跨重启文本缓存；普通读取仍保留受控缓存/并行。即使平台返回相同大小与修改时间，明确刷新仍读取新名称与执行正文，不从Workflow快照猜执行图。

Datang保留真实值写入、before/after事务和旧前端缓存检查；去掉额外graph.change，单次编辑只产生一次实际变更。隔离场景停止操作后没有继续通知。这不等于已修复云端持续草稿失败的底层原因。

## 验证与交付

新增原生保存/旧入口去重、首次发布、内部保存、失败、草稿/索引排除、跨工作流、未保存编辑、同文件合并、坏图、上传中切换以及等大小等时间缓存更新的行为回归。槽位界面继续验证实际输入、切换、重载、排序和空闲无循环。完整数量和白名单哈希以本轮交付核验为准；不能用自动结果替代云端浏览器/Photoshop验收。

更新时使用完整PS_AI dev.141、Datang0.4.61程序目录和纳贝0.4.11程序目录。保留现有工作流、图片、模型、密码、授权及浏览器草稿。更新后刷新已保存工作流页面，让新脚本加载；修改槽位并正式保存，再在纳贝刷新重连核对。若PS_AI提示自动发布失败，应保留该错误内容并处理发布失败，不重置旧有效功能。

正式源码未覆盖E盘部署或云端安装，未启动实例、生成图像、重启、提交Git或关机。既有用户资料和旧交付保留。
